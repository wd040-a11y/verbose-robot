# 추출기 성능·호환성 안정화

이번 변경은 추출기와 호환성 검사 코드에 한정됩니다. 재생기 UI, 챕터, 스토리 순서, 외부 AI API 기능은 추가하지 않았습니다.

## 기본 사용
게임 폴더를 선택하면 ‘스토리 감상용’이 기본입니다. 맵·이벤트·원본 명령·조건·분기·공통 이벤트·리소스 참조를 유지하며 원본 대량 보관과 추가 LLM JSONL은 만들지 않습니다. 필수 스키마 및 원본 재구성·개수 검사는 항상 실행됩니다. 전체 보관이 필요하면 ‘전체 보존·상세 분석용’을 선택하세요. 기존 Python Options() 기본값은 API 호환성을 위해 전체 옵션을 유지하고, GUI와 CLI의 사용자 기본값만 감상용입니다.

- `Story.zip`: 재생기에 불러올 경량 패키지. manifest, normalized, events, schemas 포함. 미디어·원본 보관·추가 분석 자료 제외.
- `assets/`: 복사·복원한 미디어. 별도 ZIP으로 연결할 수 있습니다.
- `reports/performance.json`: 단계별 경과 시간·처리 파일 수·바이트·프로세스 최대 메모리 및 검증 범위.
- `reports/resource_diagnostics.json`: 원인별 파일 목록과 명령별 리소스 참조 상태.
- `reports/integrity.json`: 원본 이벤트 재구성 및 개수 일치 결과.

## 검증 속도가 느렸던 이유와 수정
기존 finish()는 전체 패키지를 두 번 읽고 검증했습니다. JSONL의 모든 행에서 모든 데이터 유형의 조건부 스키마를 검사하는 비용도 반복되었습니다.

개선본은 전체 검증 한 번 후 변경된 최종 보고서 4개만 다시 검증합니다. 공통 envelope·$defs·해당 data_type의 스키마는 모두 적용하며, 알 수 없거나 잘못된 유형에는 전체 검증기를 사용합니다. JSONL은 한 행씩 읽고 취소를 확인합니다. 생성 시점의 메모리 객체만 믿고 디스크 검증을 생략하지 않았습니다. manifest/report/validation의 상태·검증 결과 일치도 확인합니다.

복사와 복원 도중 SHA-256을 계산해 정상 미디어를 해시 계산 목적으로 다시 읽지 않습니다. 이미지 구조 검증은 유지합니다. 성능 단계에는 중첩 구간이 있으므로 모든 seconds 값을 더하면 총시간이 되지 않습니다. RSS는 단계별 신규 할당량이 아니라 프로세스 최고 사용량입니다.

실측 수치는 `extractor-performance.json`을 확인하세요. Linux의 동일 합성 입력, 별도 새 프로세스, 동일 전체 보존 옵션으로 비교했습니다. 이벤트 1,001개, 명령 29,010개입니다. 단일 비교 측정이며 실제 사용자 게임이나 Windows에서 같은 속도 향상을 보장하지 않습니다. 두 결과 모두 스키마·원본 재구성·개수 검사를 통과했고 이벤트 shard 데이터가 같았습니다. 메모리는 감소했다고 주장하지 않습니다.

## 폴더 및 부분 실패
루트 data, www/data, 중첩 www/data, VX Ace Data/표준 아카이브를 유지·검증합니다. 핵심 파일 파싱과 최대 3개 맵 표본을 이용해 후보를 평가합니다. 비슷하게 유효한 후보는 임의로 합치지 않고 게임 이름·경로·맵 수로 선택합니다. 모든 맵은 실제 추출 때 파싱하므로 표본 통과가 전체 정상이라는 뜻은 아닙니다. 맵/이벤트 0개와 파싱 오류는 정상 완료로 표시하지 않습니다.

이미지 실패가 있어도 가능한 스토리를 보존합니다. GUI는 스토리와 이미지·영상·음성 상태를 구분하고 반복 오류를 코드별 건수로 묶습니다. 상세 경로는 보고서에 남습니다. 원본의 빈 그림 이름은 empty_name, 비문자열 이름은 unconfirmed로 구분합니다. 실제 파일 미발견, 옵션 제외, 복원 실패는 각각 별도 상태이며 재생기 연결 성공을 의미하지 않습니다.

## 실패 리소스 재시도
정상 원본 또는 System 데이터를 준비한 뒤 ‘실패 리소스만 재시도’를 누릅니다. 현재 게임 폴더와 키를 다시 읽고 실패·미지원·복원 제외 항목만 처리합니다. 정상 항목을 재처리하지 않으며 이전 출력도 바꾸지 않습니다. 새 폴더의 ResourcesRetry.zip을 기존 재생기에 추가하고 retry-report.json을 확인하세요. 키를 추측하거나 보고서에 기록하지 않습니다.

여러 게임 후보가 섞인 입력과 RGSS3 아카이브의 선택적 재시도는 지원하지 않습니다. 이 경우 새 전체 추출을 사용하세요. 전체 재추출 간 자동 캐시 재사용은 구현하지 않았습니다. 입력·옵션 변화의 검증 없이 이전 결과를 재사용하지 않기 위한 제한입니다. 저장 공간 부족 시 보고서 쓰기 자체가 실패할 수 있으므로 남은 출력 폴더를 정상 완료로 취급하지 마세요.

## 검증 범위
합성 MV/MZ/VX Ace, 중첩 경로, 다중 후보, 표준 암호화·키 누락·손상, 부분 파싱 실패, 빈 이벤트, 10,000행 JSONL과 취소, 기본 Story.zip, 재시도 리소스의 기존 재생기 연결을 검사합니다. 실제 사용자 게임 원본이 없으므로 실제 게임 호환성을 검증했다고 주장하지 않습니다.
